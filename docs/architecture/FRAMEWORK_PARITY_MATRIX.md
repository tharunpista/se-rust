## C. Things the charter asks for that upstream does **not** have

Charter §6 (multi-model team orchestration) has **no upstream analogue**. OpenCode has subagents and a job system; it has no task DAG across several providers, no ensemble-on-one-subproblem, and no cross-model adjudication. Rows 14–17 are therefore original design, not a port — the highest-risk work in the plan, and the reason the charter demands mock-provider tests before any live run.

## D. Status of the charter §11 carry-over list

**Verified row-by-row by an independent Phase 0 security review** against the code at `fe761a0`; six of the thirteen original rows were wrong in some direction. Corrected table:

| §11 requirement | Status | Evidence |
| --- | --- | --- |
| Typed provider error taxonomy; no substring routing | **overstated** | `is_retriable()` does match variants only (`se-provider/src/lib.rs`), but two helper functions that decide *which variant an error becomes* — `looks_like_a_policy_refusal()`, `is_timeout()` — do match substrings of provider text. Both are documented at their definitions and both outcomes are equally non-retriable, so this is a severity-labelling correction, not a bypass. |
| No auto-retry of auth/policy/invalid-request | **true but vacuous** | `is_retriable()` has no production caller anywhere in the workspace — only its own definition and unit tests reference it. The invariant becomes load-bearing only once the first retry/failover caller lands (Phase 4). |
| Credential redaction on request/transport/log paths | **partial** | `first_line()` redacts error bodies; two `Transport(t.to_string())` sites bypass it, and `origin_of`/`check_origin` echo a userinfo-bearing URL verbatim in an error message — the same root cause as the userinfo row below, not a separate defect. |
| Reject URL userinfo | **OPEN, worse than originally stated** | Not just unimplemented: `is_safe_origin()` accepts any `https://` string before examining the authority, and `origin_of()` keeps userinfo in the computed origin, which then gets **written into the keyring `#origin` pin** and echoed in `check_origin`'s error text — a credential-in-URL leaks through the error path, not just the request path. |
| Credentials bound to approved origins | **unit-tested, three residuals** | E2, commit `5ea3ee1`. Residuals: userinfo survives into the pin (above); "no pin recorded" returns `Ok` and keyring read errors are swallowed, so a same-user attacker who deletes the pin row restores the pre-E2 path; `with_fixed_key`/`with_fixed` are `pub` and bypass the pin check entirely for any non-test caller. |
| HTTPS required, loopback exception | **true for credential-bearing services only — new gap found** | `is_safe_origin()`'s HTTPS requirement is gated `if self.service.key_required`. | Redirects must not leak credentials | **implemented, not test-named** | `.redirects(0)` on the shared agent; no test in the file's test-name list exercises this specifically — status corrected from "unit-tested" to "implemented, needs a named test." |
| Request/stream/turn deadlines and outcomes | **unit-tested** | `1272bfd`; bound is turn deadline **plus** idle timeout, because the deadline is cooperative. |
| Deterministic cancel-vs-deadline precedence | **OPEN, confirmed** | The tie-break logic exists at two sites (`provider_runner.rs`, and a second override in `engine.rs`) but no test in the workspace sets both a deadline and a cancellation flag at once — confirmed by grepping every cancel/deadline test name.
